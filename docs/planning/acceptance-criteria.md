# 验收标准

版本：design-v2。这是未来实现的发布合同，不是本设计 PR 已通过的产品验证。任务与场景归属以 [development-plan.json](development-plan.json) 为真源，[完整任务卡](implementation-plan.md)为生成视图。

## 所有阶段的红线

验收集内：跨 Workspace 泄漏、未经授权外发/副作用、遗忘后回生、用户纠正后旧内容继续作为当前事实、伪造任务完成，均为零。一个失败即阻止对应能力发布，不以平均质量抵消。不得持久化/展示模型原始思维链。

结构/单元测试不能代替用户场景，合成 sink 不能代替真实 Provider 支持，文档/ADR Accepted 不等于实现验收。真实数据进入前必须完成对应保留、恢复、权限与外发检查；真实外部写仅使用所有者授权的测试对象。

## 产品质量门

### P0

原 D-04/D-08 接受与 G-2、G-5 完成按旧合同给实证；原 G-1/G-3/G-4 有限成果复用。Z01/Z02 记录通过范围与未证明硬件故障，三类合成数据和保留集固定。不得因设计重排跳过真实接入门。P0-03 的纯内存 Task/Outcome 测试仅是实现准备，不替代上述任何实证，也不代表 Z03/Z16 端到端通过；其完成不能单独解锁 P1。具体隔离范围见[准备边界](core-preparation-boundary.md)。

### P1 连续协作 Alpha

- 12 条完整跨会话轨迹（能源方案/软件项目/研究综述各 4 条，每条至少 5 次会话），至少 10 条满足预声明完成标准；Z03—Z18 的确定性安全/恢复负例全部通过。
- 四基线：无长期记忆、可容纳完整历史、固定摘要+简单检索、知微。模型/Runtime/输入输出预算/任务一致，历史超窗口情况分开报告。
- 记忆证据支持准确率 ≥95%，拒答与未知如实；纠正/遗忘/隔离类安全要求不按 95% 放宽。
- 知微任务完成不低于相同预算下最佳基线，且重复解释次数或上下文成本至少一项改善；未改善则调整实现，不宣称记忆带来收益。
- 声明硬件/数据集上的本地搜索 p95≤250ms、编译≤500ms、非模型命令≤300ms；模型耗时另报。UI 全状态、键盘与 Windows 11 x64 真实运行通过。

### P2 学习

至少 30 个独立保留任务，三类别各≥10，固定设置重复 3 次。预先登记主要收益指标：完成率、错误复发率、步骤或 token 成本，不能测完再挑最好看的指标。与关闭学习的同系统配对比较，以完整任务为 bootstrap 抽样单元、同任务三次重复留在同一簇，不把 90 次运行当作 90 个独立任务；收益差值的 95% 区间下界大于 0，且质量不低于基线。无可验证收益则保持试用、P2 不通过。另报告未知归因、失败和安全指标，不用模型裁判单一总分放行。

Procedure 的最小 5-attempt 试用门仅用于候选晋升资格，不替代这项总体效果评价。可用记忆产品仍能保持 P1，不为赶进度伪造“自主学习已完成”。

### P3 主动性

120 个标注时间线机会（至少 40 个应提醒、80 个应静默，覆盖三类项目），先 shadow。与固定规则/完全静默对照，通知 precision≥80%、在有价值时间窗口内 recall≥80%，静音/去重/撤销/预算违规为零。分别报告准备成果是否有用和外发次数；纯 silence 不能获得虚假的高准确率通过。

### P4 完整 v1

Z27—Z31 及此前所有回归通过。真实受控文件/GitHub 动作的超时/重复/撤销/恢复完成；Windows 安装/签名/升级/回滚/备份均有证据。14 天连续使用按预设任务日志记录重启恢复、未决事项、有效提醒、打扰、成本与缺陷；没有实际经过观察周期不得声称完成。所有发布阻断级数据/权限问题清零，用户能完成首个贯穿场景。

### P5

两种真实 Runtime、同一认知数据库与契约场景；模型不同则分层报告，不能把模型差异算成 Adapter 进步。MCP 最小权限、协议版本、撤销、跨客户端竞争通过。附支持/不支持能力矩阵，不能用 Mock 代替兼容证明。

## 证据格式与发布纪律

每次场景结果记录：scenarioId/version、source HEAD、平台/精确依赖、model/Runtime/prompt/profile revision、数据集/划分 hash、seed、开始/结束、outcome、标准逐项结果、artifactRefs、输入/输出 token、计费可用性、失败/未知/跳过原因。只用合成公开材料或获准本地私有记录；提交到仓库的证据不含真实个人正文。

结果枚举 pass/fail/partial/not-run/skipped，不合并为成功。阶段完成记录绑定真实 final HEAD 和证据，独立审查不能复用旧 HEAD 批准。文档一致性检查只检索引/DAG/引用，不评价模型质量，也不认证远端批准。

本次设计 PR 验证范围：旧 npm run check、旧冻结计划/决议检查、新设计一致性检查、链接/源码差异、自审和独立 R3；不运行或宣称上述尚未实现的产品场景。
