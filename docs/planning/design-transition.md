## 旧决议与新选择

旧 D 编号是原冻结计划与有限证据登记；新 ADR 不伪改其历史状态。[current-decisions.md](current-decisions.md)继续表示原正式接受记录；新产品选择以 ADR 0016/0017 和引用合同为准。

| 旧决议 | design-v2 已选择 | 剩余实施证据 |
|---|---|---|
| D-01 | 合同/输入记录原则保留，P1 就组合记忆快照 | 真实发送与重建范围 |
| D-02 | 单库前向迁移与完整 manifest，v1/v2 明确分隔 | 新生产迁移/中断/恢复 |
| D-03 | 保留强校验，声明负载与 p95 预算，不宣称硬件断电保证 | P0-02 实测，失败则优化或新 ADR |
| D-04 | 最小元数据/受控正文、即时失效/分项清除、恢复先对账 | 原有限登记 P0-01；生产 P1-02/P4-06 |
| D-05 | committed 确认、事务 Outbox、版本水位、gap 显式 | P1-04 故障/重放 |
| D-06 | revision/CAS、原子纠正、epoch 与依赖失效 | P1-05/P1-06 并发负例 |
| D-07 | 固定工具链与 CLI JSONL 保留 | P1-03 正式消费者 |
| D-08 | 窄工具 Broker、数据 API 独立权限、外发双重检查 | P0-01 有限登记；P1-03/04 真实路径 |
| D-09 | 单 Daemon writer、事务 lease/epoch、未知动作核对 | P1-04/P4-02 进程/并发 |
| D-10 | 固定组合与唯一 owner 保留 | 各新入口复用相同核心规则 |
| D-11 | Web 先行、Electron/Windows 11 x64、文件/ICS/GitHub、P4 v1 | 安装/签名/凭据/服务 API 实测 |

“已选择”表示设计定案；“剩余证据”不是把设计问题留给开发者，而是不能在实现前假称运行安全、性能或第三方支持已证明。有限旧决议不得被新 ADR 扩写成更广的实证保证。

## 回滚

当前仅设计/规划/检查增量，可通过新的受审 PR revert，回到旧入口与 M0 配置。先用反向应用验证恢复原树，不 reset main。原 Issue/PR/审核证据保留。

一旦后续产品 PR 消费新合同，回滚需分析依赖并按各任务恢复协议处理；不能只改路线图掩盖不兼容实现，不能从旧备份恢复已遗忘内容或已撤销授权。
