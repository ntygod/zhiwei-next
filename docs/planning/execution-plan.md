路径：`packages/protocol`、`packages/domain`、`packages/memory-store`、`packages/pi-adapter`。处理 D-01/D-04，记录 Runtime、模型、能力、策略与 config revision。M0 只覆盖无记忆会话，Claim 引用和记忆水位由 M2-3 扩展。可重建内容需要获准正文或可解析不可变引用，hash 不能替代内容。区分事件回放、输入重建和输出复现；先用脱敏证据验证合同，真实路径在 M0-4/M0-8 证明。覆盖缺失引用、摘要漂移、模型可见但未记录输入、配置半应用。不保存原始思维链，不编造供应商未开放内容，不提前注入长期记忆。

### M0-4 · 正式 Adapter

路径：`packages/pi-adapter`、`packages/protocol`。处理 D-07/D-08，依据观察、隔离、恢复和部署证据选定一种正式 SDK/RPC 路径。分别映射 Request/Response、Runtime Event、Process Boundary 和来源序列域；正常、工具、取消、Retry、Compaction、Session Replacement 有合同。用固定依赖、合成 Provider 和受限工具取证。拒绝非法 framing、EOF 尾片、错误关联与不支持能力；接受 Prompt 后的 Provider 失败不能变成成功。禁止顺手升级 Pi、接入第二 Runtime 或把 Pi 类型引入领域。

### M0-5 · Supervisor

路径：`apps/daemon`、`packages/pi-adapter`、`packages/protocol`。处理 D-08/D-09，明确状态机、资源 owner、启动/关闭排空边界和恢复会话。正常退出、异常、取消、未知执行结果分别表达；进程、监听器、连接均有释放路径。覆盖启动失败、断流、重复 stop、active/idle 终止、宿主重启和孤立进程。不做 Scheduler/Delegation，不假设不同平台信号语义相同。

### M0-6 · 摄取与领域证据
