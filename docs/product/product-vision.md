# 产品愿景：长期合作的个人 Agent

状态：design-v2 目标合同；当前实现见[交接](../planning/next-task-handoff.md)。开发顺序见 [P0—P5](../planning/roadmap.md)。

## 用户与价值

知微首先服务于有长期项目、会反复修改目标、需要研究/创作/开发的人。任务持续数天到数周，涉及多次会话、多份材料和可检验产物。跨日项目是首个验证场景，不限制用户只能处理代码；个人生活事务通过相同目标、承诺和授权模型逐步覆盖。

它应记住用户确认的约束，理解项目当前状态，承认未知，完成可检查的任务，从成败改进下次做法，在有价值时提前准备或提醒。更聪明表现为任务质量提高、重复解释减少、纠错后行为改变和合适的主动帮助，而非记忆条数或模型调用次数增长。

## 贯穿场景

以下全部为合成演示：用户要在两周内完成“家庭能源改造方案”。

| 时刻 | 用户行为 | 知微行为 | 验证点 |
|---|---|---|---|
| 第一天 | 给目标、预算、材料目录、期限 | 建项目与完成标准，区分确认预算和待调查报价，开始获准分析 | 不把估计当事实，不扩大读取范围 |
| 同一天 | 整理比较表 | 产出带来源草稿，显示检查项与待核实项 | 文件存在不等于内容合格 |
| 第二天 | “继续昨天的方案” | 展示进度、未决项、下一步，然后继续 | 不要求重述已知约束 |
| 第二天 | 缩小预算 | 新版本生效，旧方案需要重检，说明受影响事项 | 旧预算不进入新上下文 |
| 第三天 | 指出比较方法遗漏 | 保存失败经历，改进做法进入试用 | 有失败与采用证据，可撤回 |
| 截止日前 | 用户未发起会话 | 获准检查发现缺口，先准备摘要，再在预算内提醒 | 为什么现在和为何未行动清楚 |
| 执行阶段 | 授权联系指定服务方 | 在对象/内容/次数/时间范围执行，不确定时核对 | 不重复发送，不把沉默当授权 |

软件项目与研究综述作为迁移场景，防止只适配一种模板。高风险专业决策不自动执行。

## 产品承诺

| 能力 | 用户获得什么 | 首次阶段 |
|---|---|---|
| 连续协作 | 对话、项目、任务、产物同一工作台，重启可继续 | P1 |
| 可改的理解 | 查看依据、纠正、限制范围、遗忘，反馈影响后续行为 | P1 |
| 有结果的执行 | 可停止、看进度，区分完成/部分/失败/取消/不可验证 | P1 |
| 可验证学习 | 自动候选、学习审阅、做法试用/晋升/退役 | P2 |
| 主动帮助 | 目标/承诺/变化驱动，可调安静时段和频率 | P3 |
| 有界委托 | 后台运行、具体授权、审批、失联恢复与回执核对 | P4 |
| 完整桌面 | 安装升级、托盘、通知、备份、凭据和首批连接器 | P4 |
| 跨 Runtime | 第二种真实 Runtime 使用相同认知/权限合同 | P5 |

完整本地产品 v1 的完成线为 P4；P1 是能力受限的可用 Alpha。P5 是后续扩展，跨设备同步与移动审批属于条件任务，不阻塞本地产品。

## 用户控制

首次使用：选择本地数据目录、创建 Workspace、配置一个模型及其外发范围。无模型时可用明确标识的演示数据了解界面。文件目录、连接器和通知分别授权，默认无全盘扫描或自动发送。

普通输入按语义区分请求、事实、纠正与临时假设。随口提到想法不能自动变成承诺；系统提出建议，经用户确认才创建长期 Goal/Commitment。显式“记住/以后按这个做”可以立即形成有原话证据的偏好；自动推断按学习规则处理。

长期偏好可以经确认共享到 Global，项目资料不能自动升为 Global。切换 Workspace 必须可见，本轮共享偏好可查看并禁用。

## 非目标

首版不训练基础模型，不建设多用户组织、通用插件市场、自由运行的多 Agent 群体或自主改写核心代码，不兼容旧知微数据库。不承诺全天候无误或无限上下文。扩展须由具体场景和新决策驱动。

成功标准是跨会话任务、纠错生效、重复解释负担和主动帮助价值；样本、阈值、对照见[验收标准](../planning/acceptance-criteria.md)。验收集要求安全违规为零，不将其宣传为真实世界零风险保证。
