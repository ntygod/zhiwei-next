# 自主变更风险模型

风险等级决定证据、审查和合并门禁，不决定 AI 是否拥有开发权限。

## R0：机械性

典型变更：

- 拼写、链接、格式；
- 不改变语义的注释；
- 纯设计稿或历史记录；
- 已发生事实的路径同步。

门禁：

- `npm run check`；
- 作者 AI 自审；
- 无需独立审查；
- 可自主合并。

## R1：局部可逆实现

典型变更：

- 当前模块内的功能或修复；
- 新增确定性测试；
- 可回滚的小型依赖；
- 不改变协议、数据和安全边界的重构。

门禁：

- 完整自动化检查；
- 用户场景或不变量测试；
- 作者 AI 自审；
- 可自主合并。

## R2：结构性变化

典型变更：

- 架构、包边界或进程职责；
- 领域状态、作用域或生命周期；
- Runtime 协议、事件和关联键；
- 数据库 Schema 和前向迁移；
- 大型依赖、跨模块重构；
- `AGENTS.md` 和普通 Harness 语义变化。

额外门禁：

- ADR 或明确的长期决策记录；
- 回滚/恢复方案；
- 兼容或迁移说明；
- 新的独立 AI 上下文审查当前 HEAD；
- 可自主合并。

## R3：高影响与治理根

典型变更：

- 安全、隐私、凭证、远程数据发送；
- 用户遗忘、物理删除或不可逆迁移；
- 自动外部行动和权限默认值；
- 自动合并、CI 信任边界、发布和签名；
- 修改任意 GitHub Actions 工作流、安全红线或质量门；
- 生产发布和破坏性恢复。

额外门禁：

- 威胁/滥用场景；
- 真实恢复或回滚证据；
- 失败与部分完成语义；
- 独立 AI 审查当前 HEAD；
- 变更后可观察性；
- 可自主合并，但不得静默发布不可逆行为。

## 机器推断的最低等级

PR 可以声明更高风险，不能低于以下推断：

- 仅 `docs/**`、Markdown、注释和模板：通常 R0；
- 普通应用或包实现：至少 R1；
- `packages/domain/**`、`packages/protocol/**`、`packages/memory-store/**`、`package.json`、架构 ADR、`AGENTS.md`、`docs/harness/**`：至少 R2；
- `SECURITY.md`、信任与安全文档、任意 `.github/workflows/**`、删除/隐私/凭证相关文件：至少 R3。

机器推断只是下限。实际行为更高风险时，作者必须主动上调。

## 治理变更

任何影响未来 Agent 行为、验证门禁或合并权限的变更都标记 `governance-change: yes`。治理变更不能依赖同一 PR 新增或放宽的规则获得通过。
