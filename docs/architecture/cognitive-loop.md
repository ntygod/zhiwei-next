# 认知循环与上下文合同

状态：design-v2；P1 实现基本执行与记忆使用，P2 增加学习性选择，P3/P4 扩大主动与委托。

## 一次请求的端到端流程

1. API 验证身份、Workspace、schema、幂等键与 revision；记录用户 Observation 和请求。
2. 建立/关联 Task，保存用户目标与验收标准。简单问答不强制建立长期 Goal；需要持续跟踪时提出并确认。
3. 加载 WorkingState、获准环境快照、相关未决项、能力与预算，确定哪些问题需要检索/验证。
4. 先过滤范围、隐私、生命周期、有效时间和依赖版本，再按目标相关性检索。无法证明资格的条目不进入候选集。
5. 编译不可变 ContextCapsule 与 SessionContract；提交请求快照后才能派发 Runtime。
6. Runtime 的所有模型发送与工具入口通过 policy/epoch 检查；流式和最终内容在接收、物化、发布时也检查派发绑定，稳定事件逐批提交。已失效请求的临时 UI 内容立即撤下。
7. Runtime settled/取消/故障后收集 Artifact 与检查结果，由 Verifier 决定 Outcome；提交事务重验 taskAttempt、Task.intentRevision、cognition/policy/recovery epoch 与依赖，Task/工作状态/结果一同提交。
8. 形成 Episode 与学习作业，响应用户结果；学习作业失败不撤销真实任务结果，但必须显示/记录待处理状态。

## 有限认知决策

输入 DecisionInput 包括 request/Task revision、goal、workingState、qualifiedMemoryRefs、unknowns、capabilities、budget、policyEpoch。模型输出严格枚举：

| 决定 | 必有内容 | 核心验证 |
|---|---|---|
| respond | 回答草稿、依据、未知项 | 来源有效，不能伪装已执行 |
| clarify | 一个阻塞业务问题、为何影响结果 | 可逆细节自行判断，不把缺模型能力转给用户决策 |
| retrieve | 查询、目标类型、限定 scope、需要证据的命题 | Scope 只能缩小，费用/次数受限 |
| execute | taskAttempt、计划摘要、完成检查、工具需求 | 能力可用且授权成立 |
| wait | 等待条件、唤醒来源、期限 | 持久订阅而非循环问模型 |
| stop | 完成/取消/无法继续原因、保留成果 | 不能把不可验证记作完成 |

每个任务边界最多两次认知模型调用（初次及一次修复/补检索）；格式错、无进展或超限则返回明确错误/等待输入。Runtime 内部的多步执行由 Runtime 与其预算管理，不能靠不断创建新 Task 绕过限制。确定性路由能完成的继续/取消/搜索/状态查询不调用模型。

模型建议不直接写数据库；核心重验来源、状态、权限、版本和预算。DecisionRecord 只保留动作、依据与原因摘要，不要求/保存原始思维链。

### 在途请求的结果提交屏障

纠正/遗忘可能发生在最后一次模型请求在途，此后再无工具调用。收到 final 仍必须重验派发绑定，不能把它直接落为 Artifact、Outcome 或新的学习材料。纠正导致的旧结果标 stale，任务暂停/新 attempt 重检；遗忘导致的旧派生正文拒绝再物化，仅保留允许的无正文诊断。

内容写入前检查，事务发布时再次 CAS 校验；staged 内容必须登记所属 attempt/epoch，失效后立即不可读并清理，失败按清除作业报告，不能成为查询/备份/学习的输入。外部已发生的动作只核对必要回执，不因结果失效假称副作用被撤销。此规则同时适用于模型、工具、连接器与迟到学习作业。

## 上下文构成与预算

ModelProfile 必须明确上下文上限、token 计数方式、输出预留与价格信息是否可用。价格未知时以 token/次数硬上限控制，不能声称精确费用。首版默认记忆预算 min(4096 tokens, 可用输入预算的 25%)，属于工程初值。

优先顺序：安全/任务必需约束→当前请求与验收→WorkingState→明确用户偏好/项目决定→相关经历/做法→有标识的假设。用户请求和不可裁剪约束放不下时失败/拆任务，不静默截断。

记忆预算内默认：60% 当前认知与约束，25% Episode/Procedure，15% 未决项/矛盾；类别无内容时可借给其他类别。必须项超预算时返回 budget_conflict。排序用可解释因素：任务实体/关键词匹配、有效时间、已验证适用性、明确用户固定、冗余；不得只用向量相似度或访问频次。

Snapshot 保存有序材料、精确版本、内容摘要、编译器版本、模型配置、token 计数与选中/排除原因。摘要不是可重建内容：正文获准保留或引用可解析才称对应边界可重建。Runtime/Provider 隐藏变换继续明确未观测。

## 按需读取与检索

Runtime 可以调用 memory.search / memory.inspect，不能直接查询数据库或得到所有 Workspace 列表。工具边界复用相同 scope/privacy/epoch 校验，每次返回的事实与工具结果都记入请求组成/使用记录。

P1 使用 FTS5 + 结构化过滤；索引为空可用限定真源扫描并明确标注降级，不能取消资格过滤。P2 只有对照证明 FTS 漏召回时才增加本地 embedding；索引版本、模型、维度、来源版本全部记录，可重建。远程 embedding 也属于外发操作。

支持以“某时点有效”和“系统当时知道什么”两个时间参数查询。普通回答使用当前有效事实；历史回顾明确标注旧版本。冲突条目并列带来源，不能以较新的 recordedAt 自动选真。

## 记忆影响记录

- Exposure：某版本被放入某次真实请求，记录位置与原因；编译但未发送不计 exposure。
- Adoption：某版本被用于具体计划步骤/行动参数/约束，记录 step/action 与证据方式；模型自报仅为 claimed，不自动变 verified。
- Outcome：该 attempt 的检查结果。
- Benefit：有对照/用户明确比较/可观测节约的收益证据；否则 unknown。

同一记忆多次检索不等于多次成功；负反馈、失败与取消保留。为隐私删除正文后允许保留不含内容的统计身份，但禁止从派生文本恢复已删除语义。

## 验证结果

任务创建时确定 criterion 与验证器类型：artifact（存在+schema/内容检查）、tool-receipt（具体操作回执）、deterministic-test（测试/查询）、user-confirmation（主观目标）、model-assisted（建议评审，不能独自批准安全或外部副作用成功）。

执行前明确最低通过条件；未知项存在就 partial 或 unverifiable。验证器异常保存 unknown/error，不能算 fail 的反向成功。修改验收标准需用户或明确授权来源的新 revision，重做相关验证。

## 例子

用户将预算从 10 万改为 8 万（合成数据）：新 Observation→新 Claim/Goal revision→旧版本失效→计划与未发送 Capsule 作废→正在运行的任务在下一边界暂停并重编→新结果按 8 万检查。历史产物保留且标“基于旧预算”，不能悄悄重写历史，也不能继续拿旧产物支持新结论。
