# 完整产品验收

状态：全部场景为 **not-run**。本次只交付架构，不声明这些产品场景通过。下面按能力与风险组织验证，不是产品实施阶段或排期。

## 1. 贯穿场景

使用合成资料或用户明确授权的测试对象，至少覆盖研究报告、软件变更和个人计划三类长期目标。每条轨迹跨多个会话/来源和一次服务重启，包含一个目标修改、一个外部变化、一次有价值主动准备及一个真实失败/未知。

主场景：交代报告 A → A 的长工具在后台运行 → 用户提出独立事项 B → 补充 A 的要求 → 旧输出迟到 → 新资料事件直达 A → 生成并验证成果 → 重启恢复未完成 B → 用户纠正记忆 → 下一任务遵守新版本。

验收证据必须来自真实 API、数据库、对象存储、Runtime 和受控执行端。Mock 可用于单元和协议负例，不能替代发布场景。

## 2. 事件与交互

| ID | 输入 | 必须观察到 |
|---|---|---|
| E01 | 重复、乱序、删除与同键不同内容 | 去重/明确冲突；来源游标不跳过未提交事件 |
| E02 | 主对话与邮件/GitHub 引用同一事项 | 正确关联 Task；无权限主体不能控制它 |
| E03 | 指代歧义或一个 Thread 多任务 | 具体澄清；不误投控制指令或扩大作用域 |
| E04 | Worker 长任务期间新建独立事项 | durable 接收确认及时；新事项可处理/排队，主交互不等待长工具 |
| E05 | 运行中兼容补充 | delivered 与 applied 区分；下一执行边界使用真实新输入 |
| E06 | 修改目标后旧 final 迟到 | 旧结果不能成为新版本成果；新标准实际生效 |
| E07 | Router/Worker 忙时取消或撤权 | 控制面立即阻止新派发；在途效果如实核对 |
| E08 | 异步 Job 输出/完成事件与断线；Runtime 先 settled、必要 Job 后完成 | Task 等待必要 Job/input/child，不提前 partial/unverifiable；事件唤醒继续，无模型轮询或重复执行 |

## 3. Runtime 与执行

| ID | 输入 | 必须观察到 |
|---|---|---|
| R01 | 固定 Harness npm 制品、Profile/Bundle 与类型 | 精确版本/摘要/peer 解析一致，公开插件侧 Agent API 真实可用 |
| R02 | 宿主有额外配置、插件、AGENTS、凭据 | 只加载显式受信资源，不发生自动发现 |
| R03 | streaming 时 steer/followUp | 队列顺序和进入边界与官方合同一致 |
| R04 | abort 与运行中的外部 Job | 原生 idle 与外部停止分别有证据 |
| R05 | 各工具调用路径及嵌套工具 | 全部经过 Gateway；旁路拒绝 |
| R06 | 每次实际模型发送 | 来源/目的地/预算/撤销检查有效，未知路径不放行 |
| R07 | 思考输出、错误、压缩与崩溃 | 持久介质、日志与导出无原始思维链/秘密 |
| R08 | Session 替换/宿主重启 | 新身份与监听正确重建，未伪装原生续跑 |
| R09 | 依赖缺失、插件卸载/替换、跨进程 Worker 桥接和 Job 重新绑定 | 必需服务未就绪不启动业务；有序清理，旧 Agent/Session 不获得新任务权，取消和回执不丢失 |
| X01 | 多 Worker 同时修改同一对象 | 单写者/版本冲突，独立工作可并行 |
| X02 | 写动作已执行但响应丢失 | 幂等核对或 unknown；不重复外部效果 |
| X03 | 重试、子任务、并发预算预留 | 总额度不超限，不通过新 Task 重置 |
| X04 | 文件存在但内容错误、工具成功但目标失败 | Outcome 为失败/部分/未知，不能自证成功 |
| X05 | 必需标准缺证据或验证器异常 | unverifiable，不以缺少失败当成功 |
| X06 | 真停滞、正常长任务、合法等待 | 能区分并进行有界恢复，无盲目重启 |
| X07 | 旧远端写在途，lease 到期，另一 Task 竞争同资源，旧请求迟到 | quarantine 不自动释放；只有最终性证据或资源端原子 fencing 才允许冲突新写 |

## 7. 效果、性能与持续运行

三类跨日任务各至少 4 条、每条至少 5 次会话，以无记忆、固定摘要+检索、完整系统作为同模型同预算对照。报告实际完成率、重复解释、用户主动追问进度次数和成本；未知与失败单独计数。

学习用独立保留任务和关闭学习的同系统配对比较，预先确定主要收益指标，不事后挑选最好看的结果。少量案例只支持局部经验，不宣传普遍“越用越聪明”。

主动性使用至少 120 个标注机会，覆盖应准备/应提醒/应静默；通知 precision 与有价值窗口 recall 目标均≥80%，静音/去重/撤销/预算违规为零。单独评估准备成果是否可用和被采用。

在声明的硬件/网络/数据规模下测试接收、查询、检索和恢复预算；模型耗时与外部系统耗时另报。默认配置至少经历 14 天真实经过的持续运行观察，记录重启、未决事项、通知负担、费用和泄漏/重复动作；不能用快进时钟冒充该观察周期。

## 8. 发布与证据

每条证据包含场景版本、source HEAD、平台、制品摘要、模型/Runtime/profile/Prompt 版本、数据范围、时间、逐项结果、artifactRefs、成本、失败/未知/未运行原因。源内容保持合成或获准，不提交私人记录。

全部安全不变量的确定性正反例必须通过；产品效果和性能指标不得用结构检查代替。发布制品必须完成自己所声明的部署模式、设备和 Runtime 验收。部分能力未通过时明确禁用或收窄产品承诺，不把完整设计描述成已经支持。
