# 身份、权限与数据安全

状态：SA1 设计；不是已经通过的安全认证。保护对象是用户数据、持续授权、执行环境和对外身份。

## 1. 威胁与信任边界

不可信输入包括网页、邮件、群消息、仓库文件、Markdown 导入、MCP 返回、工具输出和模型建议。可信代码包括控制面、Gateway、受信 Runtime 制品与固定适配扩展；云端/设备管理员可以控制其 OS，不承诺在恶意管理员控制下隔离本机内存和密钥。

Runtime、连接器和执行节点分别使用服务身份，不共享一个全能令牌。控制数据库、Vault 与删除控制域不挂载进 Worker 沙箱。依赖和扩展是执行代码，固定版本/摘要并审查，不能被 Agent 在线安装来扩大能力。

## 2. 云端与所有者认证

云端只经 HTTPS 提供外部 API；默认绑定配置过的 OIDC issuer/audience/subject 到唯一 Owner，验证 token 签名、时效、issuer、audience 和重放边界。未配置所有者身份时服务拒绝业务接入，不能以“首次访问者就是管理员”初始化公网实例。

浏览器凭据采用受保护会话 Cookie 与 CSRF/Origin 检查；机器端使用独立短期 token、范围和撤销记录。SSE 认证与读取范围持续检查，游标不充当权限。反向代理转发头只有来自配置可信代理才接受。

本地部署也认证，默认仅 loopback；本地监听不等于允许任意网页读取。登录身份不等于获得所有文件、模型外发或外部写权限。

## 3. 来源身份与跨渠道

Webhook 校验签名、时间窗口、sourceAccount、目标资源与事件去重。轮询连接器只读取获准对象集合。来源返回的用户 ID 保留 provider namespace；相同姓名、邮箱显示名或模型判断不能自动合并身份。

所有者通过受认证命令建立 PrincipalBinding。其他人的邮件/评论可作为工作证据，但不能自动改 Task、撤销目标或签发 Grant。订阅直通也只传递上下文资格，控制命令仍检查主体。

外部对话的 Router/Reply Session 不复用私有主对话的全量历史。每个输出注明 audience 与允许的数据类别；跨渠道引用先确认数据共享范围。

## 4. Grant 与持续委托

Grant 必须含 subject、owner/workspace、动作集合、资源选择器、数据目的地、允许类别、有效期、次数/token/费用/时长上限、撤销版本和授权证据。资源选择器使用规范化根/域名/精确对象，不把正文字符串当路径权限。

直接而具体的用户请求可在已有数据/工具范围内生成一次性授权；明确的“以后这类事情直接做”可在范围清楚时生成持续委托。边界不清的授权提议带具体对象和差异请求确认。已经授予的范围持续有效，不对每个内部步骤重复索取同一许可。

权限由确定性 Policy 返回 ALLOW/ASK/DENY。一个 Grant 必须覆盖完整 action，不能把几份各自不完整的许可拼成更大权限。未知价格而 Grant 要求货币硬上限时，必须等待可计算价格或用户明确改用 token/次数约束。

授权收紧提升 policyEpoch，立即阻止新模型发送、工具派发和 Delivery。已在途效果保留核对；审批请求绑定具体任务版本、内容版本和期限，旧回复不批准新动作。

## 5. 执行隔离

云端 Worker 运行在最小权限容器，Root filesystem 只读，独立临时目录，无宿主 Docker socket、云元数据访问或控制库/Vault 密钥。模型网络仅可达 Model Gateway；工具网络按具体 Executor 的 allowlist。

任意 shell 是高能力工具，只有获得明确沙箱 profile 与资源授权的 Task 才开放。Router/Learner 默认不拥有 shell。容器不是通用安全证明；内核、逃逸风险、文件链接与网络出口需实际测试。

Execution Agent 使用独立 OS 账号和受控目录，验证路径规范化、链接/文件身份、大小和目标版本。检查在读取之前执行，不能先读取再脱敏。无法在指定平台提供该保证的 profile 返回 unsupported。

## 6. 凭据

Provider 和连接器的长期秘密保存在部署平台的 Secret Manager/Vault，控制库只存句柄。Gateway 按具体调用使用秘密，模型上下文、工具参数、日志和产物不出现 plaintext secret。

设备注册生成本地私钥，云端只保存公钥/证书。一次性配对挑战有短期限和使用次数，注册必须由 Owner 确认。设备只建立出站认证连接；每次命令还包含单用途 action token，不能因为连接已建立就任意执行。

撤销 Source/Device/Provider 后停止新派发，失联设备的授权不能离线无限使用。SA1 默认不允许离线接纳新的外部写；已接纳动作以其短期许可和回执处理。

## 7. 模型数据与 Prompt 注入

所有上下文材料带来源、scope、privacy/modelUse 和精确版本；外部内容只以数据块进入模型。系统 Prompt 和工具定义由固定受信配置提供，不能由 Markdown front matter 的字段覆盖。

模型可能被不可信内容误导，所以权限不能只写在 Prompt 里。Gateway 限制它能读取/写入/发送的资源；高影响输出由具体验证器或用户验收。模型自评安全不是放行条件。

工具输出、embedding、摘要器、Learner、评估模型和错误处理都受同一数据目的地策略。用户选择云端部署允许配置云端存储，不自动允许向任意模型服务发送所有内容。

## 8. 内容生命周期与审计

正文、敏感摘要和附件受独立保留策略；最小审计保存动作、对象 ID、版本、结果类别与授权依据。原始思维链不持久化；原始 Prompt/工具全量转储默认禁止。

遗忘先阻止使用，再清受管副本。数据库备份、对象版本、导出副本和设备缓存各自登记删除状态。已向外部服务发送的数据不能假称已撤回；受本系统管理的副本清理失败必须可见。

恢复时先读取当前独立删除/撤销 head，旧 Grant 默认 inactive，设备凭据和审批需重新建立当前资格。不能因为备份中记录“已允许”就重新启动自动任务。

同时读取不随普通备份回退的 EffectFence，重建备份后效果和未决资源隔离。即使重新授权，也不代表旧动作未发生；不能借新 actionId 或其他 Task 绕过恢复核对。原始正文与敏感回执细节可以按保留规则清除，剩余最小效果事实只用于阻止错误重做。

## 9. 必测边界

覆盖 S01—S10：跨 workspace/audience 泄漏、伪造发件人/批准、Markdown 指令污染、路径逃逸、Runtime 直接网络旁路、secret 进入输出、撤权并发、遗忘后的迟到结果、恢复旧授权和设备掉线。安全拒绝与合法正例同时验证，不能把系统完全关闭当作安全通过。
