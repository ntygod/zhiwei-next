# ADR 0027：重建为默认云端的 Super Agent

- 状态：Proposed，待本次独立设计审查。
- 日期：2026-11-02。
- 工作项：[#132](https://github.com/ntygod/zhiwei-next/issues/132)。
- 替代：旧 design-v2 的产品架构和 P0—P5 排期；原 ADR 0002、0003、0007、0016、0018、0021、0023—0025 的冲突部分。旧文件保存在重建前 Git 历史，不原地改写其历史结论。

## 背景

所有者明确要求清空原代码仓，继续 TypeScript，以 DeepSeek Super-agent 为主要参考，完成整体架构设计，不按阶段拆分，不做 UI。部署默认云端并允许本地/混合模式；Runtime 使用现有产品。

## 决策

1. 采用逻辑 Router + 独立 Task Workers，所有长期状态由宿主持有，模型/工具 loop 由现成 Runtime 管理。
2. 输入以环境事件和用户消息为主；过滤、订阅直通、异步 Job、持续会话和独立监督是完整架构的基础能力。
3. 计算、持久状态与执行环境分离，个人设备通过受控 Execution Agent 连接，不强制迁移全部资料。
4. 主对话是连续交互身份；模型上下文按受众与作用域隔离，跨来源身份由可信绑定确定。
5. 保留证据、纠正、作用域、权限、结果验证和不保存原始思维链等原则；不照搬旧代码、旧阶段或原型的安全简化。
6. 本次退出旧实现、测试、依赖与旧 Harness 工作流；新检查只验证完整设计，不伪装旧检查成功。服务端保护不修改，当前重建的治理过渡限制单独记录。

## 备选

仅修改旧工作台无法覆盖全双工和部署边界；直接复制 DeepSeek 原型不足以提供长期记忆和个人权限语义；自研 Agent Loop 增加无必要责任。选择重建应用架构与既有 Runtime 集成。

## 后果

没有旧库迁移或兼容承诺；新产品尚未实现。完整架构需要任务路由、控制面事务、内容存储、Runtime、设备与 Gateway 的联合验收。多实例 SaaS/组织权限和 UI 设计不属于 SA1 当前交付。

## 验证与恢复

完整场景合同见 [acceptance](../architecture/acceptance.md)。本次只运行设计检查、来源核对、回滚树验证和独立 R3 审查；旧基线验证失败如实保留。恢复通过新的受审 revert 返回基线树，原个人草稿位于仓库外已校验归档。详细[重建记录](../repository-reset.md)不能被本 ADR 自行豁免。
