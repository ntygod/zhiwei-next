# ADR 0029：Markdown 内容与事务控制目录

- 状态：Proposed，待独立设计审查。
- 日期：2026-11-02。
- 工作项：[#132](https://github.com/ntygod/zhiwei-next/issues/132)。
- 替代：旧 ADR 0004、0006、0009、0017、0020、0022 中与本次内容格式/存储组合冲突的部分；证据与推断分离、纠正、结果验证原则继续保留。

## 背景

所有者询问记忆能否不用关系型数据库而采用 Markdown。记忆需要可读、可编辑、可迁移，也必须支持并发更新、来源、权限、纠正与遗忘。目标默认云端，不能把单进程直接改文件的假设扩写为可靠分布式提交。

## 决策

记忆内容采用不可变 Markdown + 受限 YAML front matter。正文与语义元数据可独立导出阅读；当前有效版本、访问资格、提交/失效和依赖关系由 PostgreSQL 事务目录管理。证据和文档放私有对象存储，搜索为可重建投影。

Task、Grant、预算、Inbox/Outbox、回执和控制状态继续使用 PostgreSQL。本方案满足“记忆内容不必存成关系型事实表”，不声称全系统无关系数据库。若所有者进一步要求完全无关系数据库，须重新比较成熟事务 KV/文档数据库，并重新证明相同合同，而非直接删掉目录事务。

用户编辑通过候选与 CAS 提交，Agent 不能直接改 Vault。纠正创建新版本并失效旧依赖；遗忘阻止使用并清副本。独立失效控制 head 防止旧备份恢复已确认失效的内容与权限。

## 备选与取舍

- 纯 Markdown/JSONL：小型离线原型简单，但需自行解决锁、事务、恢复、查询与权限，不选作完整控制面。
- Git 作为记忆数据库：版本历史不等于权限/事务，默认保留历史也不利于遗忘，不选。
- 全量关系型记忆内容：一致性集中，但可读迁移与外部编辑成本较高，不选。
- 完全依赖向量库：无法承担事实与控制真源，不选。

## 后果与验证

需要对象写入与目录发布的恢复协议；承认两个存储系统没有通用分布式事务。M01—M10 覆盖编辑冲突、孤儿、索引重建、纠正、删除和恢复。只剩 `.md` 的导出导入到新安装时不会继承旧授权或 verified 身份。
