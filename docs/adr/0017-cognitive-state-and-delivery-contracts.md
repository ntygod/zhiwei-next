# ADR 0017：认知状态、数据生命周期与首版交付合同

- 状态：Proposed
- 日期：2026-10-09
- 工作项：#94
- 被取代关系：扩展 ADR 0004 的对象分类与 ADR 0008 的认知快照目标，保留既有有限实证；不取代 Runtime v1、Ledger v1、固定工具链、诊断通道及 ADR 0014/0015 的有限接受要求。旧排期由 ADR 0016 替代。

## 背景

完整 Agent 需要回答认知如何参与行动、如何学习，以及旧证据/权限变化怎样影响在途工作。仅有抽象组件名称不能指导下一位开发者。当前仍无真实长期用户数据，可以先定案目标合同，再分阶段实施和验证。

## 决策

1. 采用五类持久认知材料：证据、经历、认知、工作状态、做法；假设有独立可证伪生命周期。scope/privacy/trust/epistemic 正交，local-only 不进入任何模型。
2. 单 Daemon 正常写入、单数据库、事务 revision/CAS、任务租约 epoch、提交后 Outbox。received/committed/projected/verified 分开。
3. 新真实正文使用明确 v2 内容引用合同与可清除内容目录；v1 表与协议保留，新 migration/转换器在 P1 实现。遗忘同步失效、异步物理清除，恢复先与不随备份回滚的可信删除记录对账。
4. Context 采用有预算的固定 capsule + 受控按需读取，先资格再相关性。任务边界有限认知决策；不自研通用执行 loop。
5. Outcome 基于预声明完成条件；学习保留 exposure/adoption/outcome/benefit，采用声明式 Procedure、试用、保留集、反例与回滚。
6. 主动性按目标变化判断静默/准备/提醒/执行；授权单独检验，通知与模型不赋权。
7. P1 本地 React/TypeScript/Vite 工作台，P4 Electron；首个正式支持桌面平台为 Windows 11 x64，Linux 为 CI/开发验证环境。macOS/Linux 桌面与移动端不是 v1 发布承诺，加入支持矩阵前需独立安装/凭据/通知/升级验收。
8. 首批连接器为本地文件，之后 ICS 只读日历和 GitHub 只读事件，P4 再接受控文件/GitHub 写操作。邮件/交易不混入首版自动执行。
9. 保持强完整性检查，性能预算以声明环境实测；设计目标不能冒充已验证性能或硬件断电保证。
10. 完整字段、状态、默认参数、失败语义分别以[领域模型](../architecture/domain-model.md)、[数据接口](../architecture/data-and-api.md)、[认知循环](../architecture/cognitive-loop.md)、[学习](../architecture/learning-and-evaluation.md)、[执行](../architecture/proactivity-and-execution.md)、[安全](../architecture/trust-and-safety.md)为合同。对应开发验收由 P0—P5 任务承接。

## 备选方案与取舍

全部记忆放单一 Claim 简化存储却混淆真值、任务与技能，不选。多库/微服务增加分布式一致性成本，首版不选。永久内嵌所有正文无法满足选择性清除，不作为新数据方案。只存摘要无法重建且不能解释来源，不选。

选择 Web UI 先验证体验、Electron 后交付桌面，是为了复用 TypeScript 与统一 UI；代价是包体、更新与 renderer 安全需要专项验收。没有假定 Electron 或 Pi 自带产品安全隔离；工具与外发边界必须被真实测试证明。

## 定案与实施的区别

本 ADR 定案目标行为和默认选择，不宣称未来 Schema、平台、性能、安全或外部服务已验证。旧 D-01/D-02/D-07/D-10 有限接受继续有效，D-04/D-08 依原流程接受；D-03 的实际性能证据和 D-09 的真实并发证据在 P0/P1 执行。D-05/D-06/D-11 的目标选择由本 ADR 与引用合同承接，不把未运行测试写成 Accepted 实证。

实施时只需解决测量与具体接线，不重新开放已经选定的核心方向。若发现不能满足合同，显式报告阻塞并用新 ADR 修改选择，不能临时 fallback 到更弱安全或更少产品能力。

## 验证与回滚

独立审查检查完整跨文档路径、状态并发、权限、学习归因和旧计划映射；新任务索引检查 DAG/来源/覆盖，原门禁全部保留。正文一经接受不语义改写；后续变化另立 ADR。

本次只改文档和规划检查。通过 PR revert 恢复旧入口/配置，历史原件保留；无用户数据或迁移可回滚。生产实施后的恢复分别遵守任务卡及内容删除不回生约束，不能因回滚代码恢复已撤销权限或遗忘内容。
