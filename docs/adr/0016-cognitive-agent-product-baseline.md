# ADR 0016：以完整认知 Agent 重组产品与交付顺序

- 状态：Accepted
- 日期：2026-10-09
- 工作项：#94
- 被取代关系：替代原 M0—M7 的产品排期与整体蓝图；扩展 ADR 0004 的领域对象，不改变证据与 Claim 分离；保留 ADR 0001—0013 已接受的有限技术/安全合同，不改写其历史正文。ADR 0014/0015 的 Proposed 决议及实际接入前验证仍须按原合同完成。

## 背景

所有者要求完整个人 Agent，并允许整体调整设计、定案开发计划。原规划包含关键记忆治理机制，但把长期协作、结果学习、主动帮助和可用界面拆到过晚的阶段；核心认知如何驱动行动仍缺少具体运行合同。实现尚处基础设施与有限实验阶段，重排产品切片成本低于沿原顺序继续铺开。

## 决策

1. 产品以跨日项目协作为首个验证场景，保持通用个人 Agent 定位。产品由执行、学习、主动三条循环组成，共享结构化真源。
2. 新增明确的 Cognitive Coordinator 应用责任：组织目标与任务、判断未知项、请求上下文、调度受权执行、收集结果和学习。它是持久状态机与有限模型决策的组合，不接管 Runtime 的通用模型/工具循环。
3. 领域分为 Observation、Episode、MemoryClaim、Hypothesis、Goal/Task/Commitment、Procedure 与运行/权限对象。Scope、privacy、source trust、epistemic status 分开；模型产物不获得事实或授权的直接写权限。
4. 学习按 Exposure→Adoption→Outcome→Benefit 记录，未知收益保持未知。做法必须具有适用条件、验证器、失败边界和版本；经过试用/对照后才晋升，可停止和回滚。
5. 主动判断以目标和环境变化为依据，静默/准备/提醒/授权执行分开；Notice 不授予执行权，忽略不等于同意。
6. 技术继续采用 TypeScript 模块化单体、SQLite、本地 Daemon、独立 Worker。首个执行路径沿用已接受 Pi CLI JSONL 方向；不提前构建通用插件框架。
7. 按 P0—P5 交付：接入前置、连续协作 Alpha、可验证学习、主动协作、可靠委托与桌面 v1、跨 Runtime 扩展。首个真实可用版本具有界面、结果收集与记忆纠错；后续阶段扩大能力。
8. 新设计事实源为 [design-v2](../planning/design-baseline.md)。旧规划保留为审计快照与需求映射，不再自动选择旧阶段的下一任务。既有机器检查仍执行，历史证据不改名复用为新场景通过。

## 备选方案

| 方案 | 结论 |
|---|---|
| 保留原顺序，仅补记忆字段 | 无法提前验证完整合作体验与学习收益，不选 |
| 自研完整 Agent Loop / 一切皆插件 | 扩大执行层和安全验证范围，不选 |
| 只做跨 Agent 记忆服务 | 可以成为后续接口能力，但不满足完整产品要求，不选 |
| 多 Agent 常驻自由协作 | 状态、成本、归因和权限难以收敛；首版固定协调者与受限工作任务，选择后者 |
| 直接自动修改所有记忆和技能 | 错误能跨会话累积；选择证据、版本、试用与可撤回演进 |

## 后果

需要在 P1 同时完成一条 UI→任务→Runtime→Outcome→记忆的窄链路，单个模块不再以“接口齐全”作为产品完成。自动学习和主动执行有独立验收，不以模型自评或检索命中替代。用户更早看到产品，旧基础成果继续使用。

本 ADR 接受的是设计选择，不证明未来产品安全、模型能力、性能、兼容性或存储迁移已实现。生产 Schema 与 Runtime v1 不在本次修改；新增正式协议/迁移必须在对应任务中版本化并验证。

## 验证、接受与回滚

本次保留全部旧门禁，新增设计与任务映射的一致性核验；运行全仓检查并由独立新上下文审查最终设计和当前 HEAD。独立设计审查前保持 Proposed，审查接受设计后才登记 Accepted；变更状态后的最终 HEAD 仍需独立 R3 批准。

回滚采用新的 PR revert 本次设计、入口和规划配置；历史计划/决议/实现/证据保持原字节或可由原提交恢复。本次无生产数据迁移、用户权限变化或外部执行。若后续实现已消费 design-v2，则禁止只回滚文档，需先按任务自身恢复合同恢复实现与数据。
