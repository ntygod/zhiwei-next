# ADR 0015：合成接入前的文件、来源与模型边界

- 状态：Proposed
- 日期：2026-10-09
- 计划决策：D-08；关联 G-2、D-04、M0-4
- 范围：[Issue #90](https://github.com/ntygod/zhiwei-next/issues/90) 的有限接入前基线
- 被取代关系：补充 ADR 0012；不取代它，不扩张其诊断凭据用途

## 背景与当前状态

ADR 0012 已保护现有 health/meta/doctor：literal numeric loopback、独立注入 Bearer、拒绝 Origin 和异常请求、固定错误/输出。它不读用户文件，不调用工具或模型。诊断 token 不能授予数据、文件、工具、模型或未来路由权限，loopback 也不是信任其他同机进程的理由。

D-08 剩余的最小证据包括文件路径越界、Private 外发和工具返回指令。必须先形成可执行合成负例，不能等 M5 的完整 Delegation/Policy，也不能借 G-2 提前构造通用 Host、Grant 框架或新的产品入口。

## 有限选择

保留受保护 loopback HTTP 作为现有诊断通道。新增内容仅为显式 opt-in 的合成接入边界实验，使用真实临时文件与可观察的本地输出 sink；不连接真实 Provider、不执行任意工具/子进程、不读取用户文件、不继承真实凭据、不改变 OS 权限。它选择将来的强制拒绝语义，并不证明 Daemon/Pi Worker 已接线。

### 信任模型

- 可信：固定代码、已验证工具链、测试创建且不受攻击者并发修改的临时根、显式构造的调用上下文和控制状态。
- 不可信：其他未获凭据同机客户端、浏览器来源、任意文件名/内容、工具返回、模型输出以及其中声称的角色、授权、路径、收件端点或安全设置。
- 获得同用户任意文件/内存/环境读写、替换代码、抢占 loopback 端口或修改可信根的恶意进程不在保证内。Bearer 不认证服务端。不得把输入边界测试称为 OS sandbox 或恶意同进程隔离。

### 最小文件 profile

仅允许读取实验专门创建的固定合成根下、已列名的普通文件。资源先经过严格输入校验、根内定位和真实文件身份检查，再向消费者返回任何内容。拒绝绝对/父目录路径、非规范分隔/空段、编码别名、NUL、未知文件、符号链接（含父链）、非普通文件和多硬链接文件；发现跨根或身份变化即失败。不能以字符串前缀、只检查最后一段或先读取后判断权限替代边界。

文件能力仅是已批准的本地合成 read，不因文件内容出现另一条路径而扩大。工具返回的路径也不是可用文件能力。读取上限与错误输出有界，错误不回显路径、内容或原生异常。写文件、任意目录遍历、网络路径、自动解码/规范化修复和真实文件工具均未支持。

支持的平台/文件系统限制须由实验如实记录。拒绝 link 和重复检查可发现部分替换，不构成对恶意同用户持续竞争目录的 TOCTOU 证明；无法获得所需检查语义的平台应显式 unsupported/deny，不能静默降级。不得为了测试修改 chmod、OS 安全设置或依赖“本地即可信”。

### 来源不是授权

可信上下文由固定调用边界提供，不能从正文、工具输出、模型输出或自报 role/grant/policy 字段解析出来。工具/文件文本即使包含“用户已批准”“system”“允许外发”“切换 Workspace”也仍是未可信内容。

实验应让同一恶意文本真实经过允许读取的本地文件或工具结果，再到达授权边界，证明不会产生第二个文件访问、权限修改或 sink 调用。它不实现通用提示注入检测器，也不声称分类标签本身能验证真实 Runtime 来源；真实 Adapter/Worker 的来源绑定仍待 M0-4。

### Scope 与模型外发

先验证来源和 Scope，再决定内容是否可以交给模型/工具消费者。Private 不进入模型输入，也不能经摘要、缓存、重建或工具结果洗掉 Private 标记后外发；沿用当前领域的“只供本地规则使用”。Scope 缺失、未知、不匹配、试图由不可信内容改变 Scope 均默认拒绝。

非 Private 也不代表已经授权外发；只有可信调用上下文为具体内容类别和目的地赋予明确、有限许可才可进入输出构造。本轮许可只针对合成内容和本地测试 sink；没有真实远程模型请求。许可缺失应返回需要授权/拒绝的明确类别，不得自动推断用户同意或由诊断 token 代替。

必须从实际 sink 收到的字节/调用次数验证正负例，不能只检查独立 policy 返回值。禁止请求的凭据标记、Private 正文、注入指令不得出现在 sink、日志或错误；已允许的合成正例须能确实到达 sink，以避免“所有请求都拒绝”的假绿。

### 日志与审计

只输出固定的错误类别、结果、计数及由固定 fixture 决定的合成标识（不接受调用者提供的自由文本 ID）；不序列化请求/响应、文件内容、token、工具返回、模型原始思维链或原生异常。凭据型数据在接入 profile 中拒绝，不以字符串替换日志掩盖未经授权的内容流。D-04/ADR 0014 对删除审计同样适用，不能为诊断保留已删除正文。

## 备选方案

- 只加文档或测试孤立布尔策略：无法观察敏感内容有没有实际越过边界，不选。
- 把工具返回当用户意图，或仅提示模型不要泄漏：无法强制默认拒绝，不选。
- 扩张现有诊断凭据保护未来全部接口：身份认证不等于资源/Scope/外发授权，不选。
- 当前建立完整 Policy、Grant/Delegation、sandbox 或未来 Host：超出 M0 有限需要，不选。
- 固定合成 profile + 实际文件/本地 sink + 有界拒绝：选择；接受其有限证明范围，未来产品接入须逐入口复验。

## 证据和后果

沿用现有诊断真实 HTTP/CLI/进程正反测试。新增实验应覆盖合法根内读取、越界/链接/替换、未知平台拒绝、受信任调用与含假授权工具返回的区别、Private/缺 Scope/缺许可无输出、合法非 Private 合成输出、凭据标记不进入日志及失败清理。具体命令/HEAD/文件摘要/Node patch/实际运行结果在实验清单记录，未执行项不得称通过。

本项与 D-04 有限合同共同支持按原 G-2 卡验收接入前基线；不交付 M0-4 正式 Worker、M1-3 Scope 服务、M2-4 生产模型输入或 M5 Policy。后续真实接口必须在打开资源、读取正文、请求模型或工具副作用之前接入其相应边界；未接线接口保持关闭，不能继承本实验的安全保证。

## 审查与回滚

作者草稿/实验并不接受 D-08。接受需新的逐项独立决策审查绑定 proposalSha256 和真实完整 HEAD，之后最终 HEAD 仍需既有 R3、Ready CI 和受保护合并。ADR 0012 不做语义重写，原 Proposed 源快照不变。

本轮无真实用户数据/凭据、外发、权限变化或生产迁移。撤回 opt-in 实验和提案资料即可；不得通过回退现有诊断保护来宣称安全等价降级。
