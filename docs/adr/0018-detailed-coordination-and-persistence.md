# ADR 0018：详细协调、持久化与恢复边界

- 状态：Accepted
- 日期：2026-10-09
- 工作项：#96
- 被取代关系：补充 ADR0016/0017 的实现架构，不改变产品方向、阶段顺序或已接受 v1/工具链/诊断合同；旧有限决议的实证前置保持。

## 背景

整体设计规定了三条循环、可治理记忆和 P0—P5 顺序，但实现仍需要确定模块端口、事务、版本、水位和跨进程调用。只说“有事务”“重验 epoch”“用独立删除记录恢复”不足以定义并发和故障时的实际行为。

## 决策

1. 模块按[详细架构](../architecture/detailed-design.md)的唯一责任与消费端口组合。cognition-core 保持纯转换，应用负责 I/O 编排，Store 保证持久完整性；不新增业务微服务或通用动态 Host。
2. 区分逻辑 Session、Task、TaskAttempt、RuntimeSession、WorkerInstance 与 source stream。每次 attempt 保存绑定和 lease；未验证的原生恢复不可用“resume”名义隐藏新执行。
3. CommitGuard 包含 read-set、Task.intentRevision、相关全局/Workspace cognition/policy 水位、recoveryEpoch、leaseEpoch 与最早资格到期时间。编译、派发、结果接收/物化/发布分别重验，单一旧快照不长期授权。
4. 采用一个正常 Daemon 写者，SQL 短事务与固定顺序 admission gate；SQL 提交登记先于外部 I/O，撤销与派发有明确线性化顺序。已派发的未知结果核对，不盲重试。
5. 生产认知使用明确 Observation v2/产品事件合同；现有 NormalizedRuntimeEvent v1 和 Ledger v1 保持原意。正文及其敏感摘要/指纹放受保留策略控制的内容对象，最小不可变元数据不复制待删信息。
6. 产品 SQLite 是认知/任务真源，独立恢复控制日志是遗忘、现有数据隐私/保留收紧与恢复世代的最小单调控制真源。它先持久化不可撤销失效意图，再更新产品数据库；故障时先对账再开放读取/执行，不假称两种介质一个原子事务。
7. 备份恢复产生新 recoveryEpoch，旧 Grant/凭据会话/自动作业不生效；删除记录缺失、落后或无法证明匹配时恢复不可用。控制日志不提供对恶意管理员同时回滚所有状态的保证。
8. 本地 API 使用版本化命令、查询、事件与明确错误；外部 cursor 绑定身份/范围/恢复世代，不能暴露其他 Workspace 的提交活动或充当授权。内部 SQLite cursor 与客户端 cursor 分开。
9. 记忆接受、检索排序、预算、冲突、Outcome、Procedure 试用、主动提醒按[认知流水线](../architecture/cognitive-pipelines.md)的有界步骤实现，模型只提供结构化建议，无法扩大状态转换或工具权限。
10. 详细表/端口/事务/场景由[架构索引](../architecture/architecture-catalog.json)建立交接映射。设计 Schema 仅在隔离数据库验证约束，不作为已应用 migration 或完整产品实现。
11. P4 备份选用版本化 ZIP 容器与 age v1 recipient 加密，使用上游 TypeScript 实现并在实施时锁定/互操作验证；不用自制文件加密格式。受管备份的保留不能延长内容许可，清除时替换/删除旧副本并如实报告残留。

## 备选方案

- 长事务跨模型/工具调用：锁时间不可控，撤销难以落地；不选。
- 各 Service 自己写库和重试：容易产生半状态与重复副作用；选择单持久协调边界。
- 只靠发送前校验：漏掉最后请求在途后的迟到结果；不选。
- 删除日志只放可恢复的产品备份内：会恢复旧记忆/授权；选择独立控制状态，承认丢失该状态会阻止自动恢复。
- 所有正文永久 append-only：无法履行清除；选择不可变版本语义与受控物理保留分离。
- 直接把内部 row cursor 当外部权限：位置不是权限，且可能暴露别的工作区活动；选择绑定范围的外部 cursor。

## 后果

实现需要明确的事务目录、read-set 与状态机，但不需要分布式消息服务。恢复先处理控制状态，不能优先恢复“看起来可用”的 UI。权限变化可能使正在生成的结果失效，这是产品正确性的一部分；界面必须说明重检原因。

新设计不证明 Pi 已能强制所有工具/模型路径、Windows 文件隔离、硬件断电持久性或未来 API 兼容。实际执行 profile 在对应任务取得证明前保持关闭。

## 接受、验证与回滚

需新的独立 R3 设计审查，核对端口/表/事务/时序/任务映射，运行原全仓检查和本次设计合同检查。设计接受与实现/接入许可分开；状态登记后的最终 HEAD 仍走原 CI、来源与受保护合并。

本次仅设计文件及其隔离验证，可通过受审 PR revert 恢复设计基线。不存在生产迁移或正文清除；后续实现消费后按其具体迁移/恢复合同回滚，不恢复已遗忘内容或已撤销权限。
