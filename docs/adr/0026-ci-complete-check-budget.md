# ADR 0026：完整检查的 CI 作业预算

- 状态：Accepted（所有者明确授权该预算；合入仍须最终当前HEAD独立R3审查与原全量检查）
- 日期：2026-10-13
- 工作项：#127 / PR128
- 被取代关系：仅补充 ADR0025 第5项的CI作业预算；原产品、运行时期限与质量门不变

## 背景

当前原完整 npm run test 已有723931ms的1174项成功记录；另一四进程试验耗时560643ms但有两项失败，不能计为通过。严格编译及工具链负例还有独立耗时。原native CI的static-contracts整项10分钟预算多次在测试结束前取消，未取得完整检查证据。

四进程调度、事务JSON复用及规范化遍历试验未证明能解决完整作业耗时，均撤回。已定位并修复实际可执行入口的加载时机，原3秒配置拒绝要求保持；记忆工具场景使用既有注入时钟并增加明确到期拒绝，真实Worker/RPC期限保持。

所有者明确答复「允许CI作业预算增至20分钟（推荐，完整执行全部检查）」。该授权仅扩大原全量检查的执行预算，不授权删除测试、放宽断言或跳过质量门。

## 决策

1. CI的static-contracts作业timeout-minutes从10改为20；原完整npm run check命令与全部步骤、权限、条件、发现规则和失败退出保持。测试文件仍使用原两个隔离进程。
2. Daemon可执行启动检查的3000ms、Worker/RPC/模型的各个原期限、fixture屏障、契约与产品性能指标不改。作业取消、任一断言失败或证据缺失仍阻止合入。
3. 唯一check observer、CI required evidence、standalone quiet/live provenance、精确HEAD独立R3、受保护合入和main来源审计保持；不得把延长预算当作成功证据。实际新的全量结果绑定候选HEAD。
4. 仅运行既有受控合成检查和原许可取证，不扩大个人数据、模型、凭据、外发或部署许可，也不重试受限旧实验/具体拒绝。若仍失败，记录真实问题并修复，不无界增加预算。

## 备选方案

- 固定10分钟反复重跑：无法保证全量检查结束，保留日志后不再无界重试。
- 减少检查或放宽测试期限：削弱验证，不采用。
- 增加测试进程或复用验证结果：本轮未证明总耗时收益，恢复原调度与原算法。

## 验证与回滚

运行原完整npm run check，实际通过全部既有检查和全量测试后才推进；预算调整本身不认证产品或源码。该R3治理改动依据所有者明确授权并遵守任务开始时原断言、批准和保护门，由新独立上下文审查最终HEAD。

回滚通过新受审revert恢复10分钟作业预算；已产生的证据和用户数据不回退，未通过完整检查时继续保持Draft与真实入口关闭。
