# ADR 0008：会话记录与模型输入重建的边界

- 状态：Proposed
- 日期：2026-10-08
- 计划决策：D-01；关联 D-04/D-05/D-09
- 被取代关系：不取代 ADR 0005/0006，不扩展 NormalizedRuntimeEvent v1

## 背景

事件回放、模型输入重建和相同输出复现是三个不同结果。现有 v1 记录 Runtime 已观察事实，Ledger 保存其 canonical body；它们没有正式 SessionContract、模型请求 Step、最终模型输入或内容保留策略。Message Snapshot 也不能证明已观察 Runtime 之后的全部请求变换。[M0-3](../planning/milestone-m0-execution.md)要求无记忆会话，M2 才引入 Claim/水位/编译器。

## 拟议决策

M0 的会话合同记录逻辑 Session 与 Runtime Session/Instance 的关联、协议版本、Runtime/模型标识、可用能力、策略和产品 config revision；合同修订不可覆盖旧版本。请求记录引用当时实际生效的合同 revision，不从当前配置倒推历史。确切字段、owner 并发与原子提交须在 D-09、M0-2/3 定案，不在 v1 payload 中偷加字段。

模型输入记录以实际观测边界为单位，保留顺序、输入组成与变换来源。可重建组成必须有获准正文或可解析的不可变内容引用，并校验摘要；只有 hash/摘要时只能证明标识，不能恢复内容。完整性按观测事实声明：缺引用、摘要漂移或 Runtime/Provider 后续变换未观察时，明确拒绝“完整重建”或返回未证明范围，不能填入猜测正文。没有原始思维链的保存例外；内容保留/遗忘与真实数据授权仍由 D-04/G-2 决定。

| 结果 | M0 范围 | 不保证 |
|---|---|---|
| 事件回放 | 按保存的 source/cursor 读回并校验事件 | 不等于上游从未丢失；不提供跨域全序 |
| 模型输入重建 | 仅获准、实际观察且保存完整的无记忆输入 | 不重建供应商隐藏提示、未观测变换或已删除内容 |
| 输出复现 | 保存实际观察的输出与关联 | 不承诺随机采样/远端状态可确定重放 |

M2-3/4 才增加 Claim 版本、认知水位、Compiler revision、胶囊与选择依据。M0 不注入长期记忆、不把 bootstrap ContextCapsule 当成已发布请求记录合同。配置变更先形成完整有效 revision 后才能供新请求引用，半应用不能伪装成功；进行中的历史记录不随新配置重写。

D-05 负责提交/摄取确认点与投影完整性：Ledger append 成功只证明该批已提交，不证明上游零丢失、投影完成或模型成功。模型输入记录不可复用一个 `accepted` 状态混淆上述事实。

## 备选方案

- 保存原始 Pi payload：违反中立投影与原始思维链限制，拒绝。
- 仅 hash/摘要：适合核对身份，不满足内容重建，拒绝作为完整方案。
- 获准正文/不可变引用：拟选；需要保留与失效策略，并明确不可重建结果。
- M0 提前实现完整记忆胶囊：违反里程碑分工，拒绝。

## 证据、接受条件与后果

目前没有请求重建实现或 E0-09 端到端证据。本提案不将 D-01 标为 Evidence Ready/Accepted。接受需要脱敏合成样本证明：正常输入重建；缺引用/摘要漂移失败；未观测变换不宣称完整；配置半应用不污染请求；旧 revision 可解释。M0-3 的单元合同验证与 M0-4/8 的正式 Runtime 路径验证分别记录，后者没有证据前不宣称产品链闭合。还需独立 R2 审查的 PR/完整 HEAD 与决策登记。

分层记录增加存储/保留成本，但不会以“事件存在”误导用户。G-1 只建立决策边界，不交付会话产品能力；D-04/D-09 和实际接入仍有独立门。

## 兼容与回滚

无 v1、Schema、迁移或运行配置变化。撤回提案只需文档回退；未来已保存会话记录的恢复/迁移需要其自身 ADR，不由本提案授权删除。
