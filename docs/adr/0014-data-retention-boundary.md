# ADR 0014：接入前的正文保留、遗忘与恢复合同

- 状态：Proposed
- 日期：2026-10-09
- 计划决策：D-04；关联 G-2、D-01、D-06、M1-5
- 范围：[Issue #90](https://github.com/ntygod/zhiwei-next/issues/90) 的有限接入前基线
- 被取代关系：不取代 ADR 0004/0006/0008/0009；不修改 NormalizedRuntimeEvent v1 或已应用迁移

## 背景与当前实现

append-only 约束历史事实不能静默被另一事实替换，不等于正文必须永久保留，也不等于写入 tombstone 就已经删除字节。ADR 0008 要求获准正文或可解析的不可变引用；失去正文时，事件存在和摘要存在都不能证明可以重建。

当前正式 Ledger 将完整 canonical event 保存到 event_json，并将 payload 保存到 data_json；消息正文、工具输入/结果和错误文本可能同时存在于这两份表示中。Schema 拒绝 UPDATE/DELETE/REPLACE，公开 API 没有遗忘或清除方法。v1 的 persistence=ephemeral 是协议分类，不是 TTL 或清理保证。当前 Claim 存储仍是内存哨兵，没有正式持久化版本、失效水位或恢复入口。

因此本决策接受前仍不允许将本合成实验称为真实数据清除能力；即使有限合同获接受，也不能从它推导现有 v1 Ledger 已适于接入需要删除保证的真实个人正文。

## 有限决策

选择“最小不可静默改写的来源元数据 + 受独立保留规则约束的正文”。这是语义和接入门槛选择，不在本轮选定新的 Schema、内容库、跨库提交协议或字段版本；后续实际数据模型必须另行版本化并履行迁移与 R3 恢复验证。不得向 v1 塞入不受协议定义的引用、删除标记，或削弱 manifest/append-only 检查。

每次真实数据接入前须明确对象类别、目的、Scope、保留终点、允许的副本/备份以及是否需要可撤销正文；未明确即拒绝接入，不能把“未配置 TTL”解释成无限期保存授权。本轮只有可丢弃的合成数据 profile，不给真实用户选择虚构的默认保留天数。

| 类别 | 保留与删除合同 |
|---|---|
| 事件最小元数据 | 仅保留解释来源、顺序、身份及执行遗忘所必需的受控标识/类别。原始路径、自由文本、工具参数、错误正文、提示词、令牌及正文摘要不是自动安全的元数据。生效期间不可静默改写；不获得永久保存豁免，完整 Workspace 清除仍须覆盖它。 |
| 正文与内容引用 | 消息正文、工具输入/返回、快照、附件、原始外部文本及含原文的配置均受正文策略控制。获准时可 inline 或用不可变可解析引用；引用、摘要、备份、重复表示随同一删除范围失效。分离语义不承诺当前 inline Ledger 可原地清除。 |
| Claim/Candidate/版本 | Claim 内容属于正文，含义、版本链、证据关系必须可追溯。遗忘立即取消可使用资格；旧版本和 Candidate 不得成为回生源。允许保留的最小版本/删除记录不复制原文。具体传播/并发由 D-06/M1-5 决定。 |
| 派生数据 | 查询缓存、索引、FTS、向量、摘要、胶囊及编译产物不是事实源。其保留不能超过输入的可使用资格；遗忘后的陈旧副本必须隔离或重建，未核对当前失效状态的缓存不得返回。重建只消费仍可使用的来源。 |
| 备份与中间副本 | 数据库主文件、WAL/journal、临时文件、导出、关闭态备份及部署管理的其他副本都须纳入清单。删除请求应报告每一类已清除/等待到期/失败/范围外状态；未知副本不得默认已清除。外部已发送内容无法追回须明确说明。 |
| 删除审计与禁止回生记录 | 只含必要受控目标标识、操作种类、授权引用、顺序/时间及固定结果类别；不复制待删正文、原文摘录、提示、路径、异常文本或正文派生摘要。其最小保留期限须覆盖仍可恢复的旧副本；这些副本已不可再恢复后才可按策略清除该记录。 |

### 逻辑遗忘与物理清除

- 逻辑遗忘是立即禁止使用的状态变化。授权覆盖具体对象/范围后，持久化失效记录先于对外报告成功；查询、检索、Context、重建、迟到消息与恢复都必须执行相同失效语义。进程中断后不能靠旧状态恢复为可使用。此处不设计未来事务字段或实现 erase engine。
- 物理清除是另一项授权和结果：删除已声明管理范围内的正文及所有列明副本。逻辑遗忘成功不得显示成物理清除成功；有未处理备份、数据库日志或失败副本时显示 partial/pending，不隐藏剩余范围。
- 本地文件不再能读取只能证明该文件路径的应用级清除结果，不能证明 SSD、文件系统快照、未受管备份或介质取证级字节销毁。未来若承诺更强物理保证，必须先完成相应证据和数据策略。
- 审计不是保留被删内容的例外。禁止将正文转存为日志、hash、摘要、失败报告或“证据”来规避清除；测试证据只记录合成用例与固定结果，不输出合成敏感标记。

### 重建与备份恢复

内容未获保留、已过期、已遗忘、被清除或引用缺失时，返回明确 unavailable 及固定原因；摘要校验失败是 corruption/unavailable，不能重新询问模型、从旧缓存、同文副本或备份偷偷补全。保留事件存在性不等于可重建模型输入。

旧备份只可进入隔离恢复区。对外查询、重建或重建索引之前，必须与不随该旧备份回滚的当前可信遗忘记录/水位对账；重新施加已有遗忘决定，再建立新投影。没有足够新的可信状态、状态缺失/损坏/不匹配或对账中断时，恢复内容保持 unavailable，不能以备份自身的“没有遗忘记录”作为授权。延迟到达的已遗忘对象同样被拒绝。

这是可信恢复协调流程的合同，不是可抵御恶意管理员同时回滚所有状态的证明。当前 Ledger 只有 append/read API，尚无此正式恢复协调器。本轮合成实验以真实关闭态 Ledger 备份证明旧正文仍可回读，再由独立保存的合成失效记录证明隔离的查询/重建输出不能恢复正文；不得只测试 policy 布尔量后宣称解决恢复问题。

## 备选方案

- 永久 inline 正文 + append-only：最少新对象，但无法履行选择性正文清除；不作为需要删除保证的真实数据默认方案。
- 只存摘要：不能重建，且摘要不是匿名化/删除证明；不选。
- 最小元数据与受控正文生命周期分离：选择。获得清楚的保留/不可用语义，但实际持久化方案仍需独立实施。
- 现在引入密钥销毁、加密内容库或通用保留框架：没有当前消费者/部署证据，超出有限基线，不选。

## 证据、后果与剩余前置

合成实验应覆盖真实临时 Ledger 的原文持久化/关闭重开/旧备份回读、逻辑遗忘后的查询与重建、引用删除后的 unavailable、备份未清除时 partial、当前遗忘状态缺失或陈旧时恢复拒绝、迟到消息/旧缓存拒绝以及日志无正文。合成文件 unlink 不是生产 SQLite 清除、在线备份一致性、断电持久性或跨进程原子性证明。

本合同允许有限 G-2 接入前政策验收；不授予真实正文保留/删除许可，不交付 M1-5，不改现有正式 Ledger。M0-3/M1-1 的真实内容表示、M1-5 的原子失效/清除与副本处理、D-06 的并发和缓存传播及真实恢复路径仍分别验收。正式接入必须满足所需门槛，不能从 ADR Accepted 自动推导产品启用。

## 审查与回滚

作者实验或起草不是决策接受。仅在新的逐项独立决策审查绑定本有限文本、proposalSha256 与真实完整 HEAD 后记录接受；最终完整 HEAD 仍按既有 R3、CI 与受保护合并流程验收。原始 D-04/工作包快照保持原文，当前执行投影单独记录状态。

本轮无生产数据/迁移/清除，撤回文档及 opt-in 合成实验即可。未来物理清除不可用 revert 撤销；恢复旧备份不得撤销已生效遗忘。
