# apps/AGENTS.md

适用范围：`apps/**`。应用层负责组合、进程生命周期和用户/机器接口，不承载认知领域规则。

## 边界

- `apps/*` 只能通过 `packages/*` 的公开入口组合能力。
- 不在 HTTP handler、CLI command、UI store 或进程启动代码中实现 Claim、Scope、Outcome、Attention 等业务规则。
- 客户端不直接访问 SQLite，也不持有长期认知真源。
- 应用层可以做输入解析、认证/授权入口、DTO 转换、依赖装配和错误映射。
- 不从应用层反向导出类型供领域包依赖。

## 进程职责

### `apps/daemon`

- Daemon 是本地数据与 Worker 生命周期的唯一协调者。
- 默认只绑定 localhost；新增远程监听必须先完成安全决策。
- 健康检查、日志和错误响应不得暴露密钥、原始记忆或模型敏感载荷。
- 需要支持优雅关闭；已确认写入不能因进程退出被静默丢弃。
- Worker 崩溃、取消和正常完成必须映射为不同状态。

### `apps/cli`

- CLI 是 Daemon/协议的薄客户端和诊断入口。
- 人类可读输出与机器可读 JSON 应来自同一结构化结果。
- 命令失败必须返回非零退出码和可操作错误，不使用成功退出掩盖降级。

### `apps/desktop` 与 `apps/web`

在对应里程碑到来前只保留边界说明，不提前实现完整产品壳。未来客户端也不得绕过 Daemon 直接读取数据库。

## 测试

优先测试接口边界和生命周期：

- 参数与输入错误；
- localhost 与隐私默认值；
- 取消、关闭和异常退出；
- Daemon 不可用时的明确失败；
- 结构化错误和退出码；
- 不把业务逻辑重复到应用层。
